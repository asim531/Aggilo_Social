Agent Hierarchy

The Five Agents — Soul to Action

Every agent inherits from AGGILO_SOUL.md — the philosophical root — via a tiered injection system that gives each agent exactly the soul material it needs.

Tier 0 — Full Soul

🟢 Clio — Orchestrator

The only agent users ever meet. Personal companion, cluster creator, and emotional intelligence layer. She orchestrates all other agents.

  • User-facing conversational AI via FAB
  • Demographic persona system (Campus 18-24, Momentum 25-35, Anchor 36-50+)
  • Platform rollout arc 1–10 (feature tiers per cohort: cluster discovery → matchmaking → DMs → premium)
  • Introduces Sage after N≥5 interactions + user opt-in
  • Crisis response protocol (overrides all other rules)
  • 2-message limit per cluster per 24h
  • LLM: Claude for onboarding/intros, Kimi K2.5 for standard turns
Tier 1 — Community Soul

🟢 Sage — Cluster Host

Active interventionist growth guide for clusters. Shapes direction using three navigational coordinates: purpose, demographic, present moment.

  • Cluster-scoped only — zero cross-cluster awareness
  • Arc phases A→E (Cold Start → Self-Sustaining)
  • Issues content briefs to Atlas (up to 3 iterative rounds)
  • Polls for RL signal, description refinement proposals
  • Welfare escalation to Clio (non-negotiable)
  • Register adjusts by arc phase: patient → honest → playful → direct → minimal
  • LLM: Kimi K2.5 standard, Claude for conflict intervention
Tier 3 — Minimal Soul

🟢 Atlas — Content Intelligence

Background content fetch and scoring engine. Finds real-world content for clusters via API/RSS-first, Chrome fallback. Never user-facing — all output goes through Sage.

  • Briefed exclusively by Sage (sole principal)
  • Relevance ≥0.80 + Demographic ≥0.80 scoring thresholds
  • Brief variants: cold / warm / depth / reengagement / synthesis_request
  • Zero-Content Protocol: synthesis_mode: true with transparent framing
  • Format detection: article, video, data snippet, thread
  • Shared Redis crawl cache (1h TTL) across overlapping clusters
  • Poll RL context injected into every Atlas brief from cluster_polls
  • LLM: Kimi K2.5 for hooks, Groq/Llama 3 8B for scoring
Tier 2 — Ethical Soul

🟢 Scout — Growth Intelligence

Read-only internet intelligence agent. Reads Reddit, LinkedIn, Twitter/X. Produces structured reports. Never posts externally — structurally cannot.

  • 20-post minimum observation threshold per community
  • Zero PII storage — paraphrased patterns only
  • 3 signal types: people, community, gap intelligence
  • Monthly accuracy calibration against real conversions
  • Clio-triggered directed discovery for unmet needs
  • 30-day stale window auto-expiry on findings
  • LLM: Kimi K2.5 for analysis, Groq for scoring
One Line Only

🟠 Aggilo Observer — Platform Intelligence

Platform-wide AI inference across 9 observation domains. Reads everything, surfaces findings to admin dashboard. Never interacts with users.

  • 9 domains: Cluster Health, Growth, Monetisation, Crowdfund, Agent Perf, Content Gaps, Underserved Demo, Safety, Scout Pipeline
  • Read + Act authority with mandatory admin approval
  • Severity tiers: Critical → High → Medium → Low
  • Safety domain runs every 2 hours
  • Daily digest aggregation to admin
  • LLM: Kimi K2.5 for inference, Groq for scoring
Data Flow

How a User Message Becomes a Connection

1. User → Laravel

Authenticated PWA user sends message. Laravel's YantraDispatcher creates a job with HMAC-signed callback URL.

2. Redis Queue

Job dispatched to priority lanes: high (real-time), medium (scheduled), low (batch). BLPOP consumer pops by priority.

3. Yantra Assembly

Context assembler builds prompt: Soul tier → Agent SOUL → IDENTITY → USER context → Job payload. Version header injected.

↓

4. LLM Router

Admin-configurable routing table. 12 operation keys mapped to providers. Claude for high-stakes, Kimi K2.5 for volume, Groq for overflow.

5. Supabase State

All state persisted: sessions, cluster data, agent memory, findings. Yantra is stateless between turns — reads at start, writes at end.

6. Response → User

Callback to Laravel with HMAC verification. Response written to Supabase. Supabase Realtime pushes to user's PWA. Latency target: <30s.

Agent Interactions

The Sage ↔ Atlas Content Loop

The most complex inter-agent workflow: Sage briefs Atlas, reviews cards, refines iteratively, then posts editorially to the cluster.

Sage Issues Brief

Contains: cluster AGGIL segment, arc phase, format preference, 72h exclusion list, poll RL context, refinement feedback from prior rounds.

Atlas Returns Cards

Scored batch with relevance + demographic confidence. Each card: headline, source URL, conversation hook, format, synthesis flag.

Sage Reviews

Checks: right depth for arc phase? Right format? Specific hooks? Local sources where relevant? No 72h repeats? May request up to 2 more rounds.

Editorial Post

Sage writes the cluster post in her communal voice ("we"), with source attribution. If synthesis, transparent framing + follow-up poll.

Cluster Lifecycle

Arc Phase Progression (A → E)

A
Cold Start

Orienting, patient. Clio holds space. Atlas serves accessible content.

B
First Friction

Honest, steady. Real opinions emerging. Sage holds conflict without anxiety.

C
Cohesion

Lighter, celebratory. Shared vocabulary forming. Deeper references.

D
Depth

Direct, substantive. Hard questions. Research-grade Atlas content.

E
Self-Sustaining

Minimal presence. Members self-initiate. Sage's highest success state.
