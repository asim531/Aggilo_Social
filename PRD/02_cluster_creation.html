⚡ Critical Rule — Duplicate Prevention: Before ANY cluster is created (regardless of method), the system MUST check for existing clusters with similar AGGIL settings and topics. This prevents fragmentation and concentrates users into stronger communities.

AGGIL Settings Configuration

Every cluster is defined by these 5 dimensions:

Dimension Icon Details
Age 🎂 DOB-based range. Manual or AI-suggested.
Gender 👤 Default: Anyone. Optional: Male/Female. Privacy-gated.
Geography 📍 Multiple Hyper-local locations (Building/Campus), Regional scope, GPS.
Purpose 💡 Core reason for connection. Drivers Scout discovery.
Tags # Multiple vibrant hashtags (Hooks). Captures emotions/needs.
Language 🗣️ Multi-language support. Primary + secondary.

Cluster Score Calculation

Factor Weight Description
Purpose & Vibrant Tags 25% Clear purpose + 3+ vibrant emotional tags = higher score
Location precision 20% Hyper-local/GPS > named city > state
Age range width 20% Narrower = more focused = higher score
Name + Description quality 15% AI checks for clarity and uniqueness
Estimated audience size 20% Balance between too narrow and too broad

🤖 Collaborative Clio: Clio extracts AGGIL parameters from natural language and deduces the ideal settings. She then presents these for user acceptance or editing before proceeding to creation. The user remains the driver, with Clio providing deep-intelligence suggestions and seeding Scout-discovered topics.

Voice (per Character Bible): Clio's conversational creation dialogue must follow the Bible's principles: she has opinions about cluster design ("I'd tighten the age range — broader sounds inclusive but it dilutes the signal"), she uses specificity over warmth ("Weekend treks, not running — that distinction matters"), and she gently challenges when duplicates are near-matches ("What makes yours different?"). she does NOT say "Got it!", "Amazing!", or manufacture urgency. Voice specifics are in the active clio/personas/*/IDENTITY.md.

📍 GPS Landmark Rule: The GPS range is measured from a fixed landmark (e.g., "Charminar" or "HITEC City"), NOT from the creator's live GPS position. Both cluster creator AND the visitor must have shared their GPS for the cluster to be visible.

Post-Spawn Editing Rules

Once a cluster has members, the Founder enters Window 2 (Post-Spawn) refinement. The governing principle: no change may retroactively harm, eject, or disadvantage a member who joined in good faith. Clio enforces these rules automatically and will not process a disallowed change.

Property Allowed Post-Spawn? Constraint
Description text & tone ✅ Yes No restriction
Seed questions ✅ Yes Full rewrite allowed
Interest tags — add / broaden ✅ Yes Can only expand discoverability, not restrict it
Cluster name ✅ Yes Clio notifies existing members of the change
Interest tags — narrow / remove ❌ No Would disadvantage members who joined for those tags
Age range — tighten ❌ No Would retroactively exclude current members
Gender filter — add restriction ❌ No Cannot apply to a cluster members joined as open
Core topic pivot ❌ No Changes the fundamental identity members agreed to
Geographic scope — tighten ❌ No May exclude members in previously valid zones
🤖 Clio's enforcement behaviour: When a Founder requests a disallowed change, Clio explains the member-protection principle once, offers alternatives within the allowed scope, and stops. She does not lecture. Pre-spawn (Stages 01–02 of the cluster card lifecycle), all parameters remain fully editable — the constraint only applies after the first member joins.
