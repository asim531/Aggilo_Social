Goal
- Render the care reach-out signal in Clio FAB when a cluster member has been flagged for welfare check, and display the Just Clio private-chat tab with the handoff greeting.

Scope
- Frontend UI only; backend tables and realtime channel exist (B11).

Requirements
- When `clio_observer_signals` contains a care-reach-out for the current user in any joined cluster:
  - Clio FAB shows a soft red pulse dot (8px, `#EF4444`, opacity 0.4→1.0, 2s loop).
  - On open, Clio chat lands on "Just Clio" tab (not cluster context).
  - Handoff greeting rendered from `clio_handoff_greetings` row: warm, non-clinical, signed by Clio.
  - Dismissing the greeting clears the FAB dot for this session.
- If multiple clusters flag care-reach-out, show the most recent one; aggregate count badge if >1.

Dependencies
- Realtime backend channels (B11) for signal delivery.
- FE08 for Clio FAB dual-tab UI and sessionStorage TTL.
- `clio_observer_signals` and `clio_handoff_greetings` tables (B09).

Plan
- Subscribe to care-reach-out channel on app mount (scoped to user_id).
- On signal: set local state → FAB dot renders; store dismissed IDs in sessionStorage.
- Implement Just Clio tab with handoff greeting fetch on first open after signal.
- Add fallback: if realtime fails, poll `GET /api/clio/care-signals` on Explore mount.

Files to Touch
- `apps/web/src/components/clio/CareReachOutDot.tsx`
- `apps/web/src/components/clio/JustClioTab.tsx`
- `apps/web/src/hooks/useCareSignals.ts`

Validation
- Signal arrives → FAB dot appears within 2s.
- Open Clio → Just Clio tab active → greeting rendered.
- Dismiss → dot gone; reload → dot does not reappear (sessionStorage tracked).

Risks & Mitigations
- Risk: Signal feels intrusive. Mitigate with soft pulse (not red banner) and easy dismiss.
- Risk: Multiple signals overwhelm. Mitigate with aggregation and single-greeting policy.

Out of Scope
- Backend signal generation (Observer welfare protocol); clinical assessment logic.
