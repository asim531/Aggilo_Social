Goal
- Prevent duplicate BullMQ job execution using idempotency keys per AGENT_RUNTIME spec.

Scope
- Queue submission wrapper and minimal tests. No worker logic changes.

Requirements
- Idempotency key format: `{agent}_{operation_key}_{related_id}_{coarse_ts}` with per-op granularity.
- Reject/skip dispatch if key already processed in dedup window (default 1h, per-job override allowed).
- Log `idempotency_collision` in runtime_events (or equivalent) when rejected.

Dependencies
- runtime_events table (F01) for collision logging (if used).

Plan
- Add submit wrapper that checks cache/storage (Redis) for idempotency key before enqueue.
- On enqueue, set key with TTL (per op) in Redis.
- On collision, skip enqueue and log event.
- Add tests for unique submit vs duplicate within window.

Files to Touch
- `apps/api/src/lib/queue.ts` (or equivalent)
- Tests under `apps/api/test/queue.test.ts`

Validation
- Run tests; ensure duplicate submit is rejected and logged.
- Manual: enqueue same payload twice → second rejected with collision log.

Risks & Mitigations
- Risk: wrong TTL per op. Mitigate by mapping per operation key.
- Risk: race conditions. Use Redis SET NX with expiry.

Out of Scope
- Worker-side dedup; downstream logic unchanged.
