Goal
- Track Clio LLM meltdown events (validator failures) and surface threshold for Observer Domain 5.

Scope
- Clio LLM wrapper and logging.

Requirements
- Count validator failures per operation key per hour; threshold: 3 in 1h triggers meltdown event log.
- Emit structured log row (to runtime_events or llm_response_logs) with request_type=clio_meltdown, op key, count.
- Integrate with retry+degrade flow (F04); no duplicate triggers in same hour window per op.

Dependencies
- Retry+degrade implementation (F04); logging tables.

Plan
- Add counter bucket keyed by op + hour in LLM wrapper.
- On crossing threshold, emit meltdown log and reset window timer.
- Add unit tests to simulate failures and threshold crossing.

Files to Touch
- `apps/api/src/services/clio/llm-wrapper.ts`
- Tests under `apps/api/test/clio-llm-wrapper.test.ts`

Validation
- Tests: 3 failures in hour → meltdown log once; further failures within hour do not duplicate; next hour resets.

Risks & Mitigations
- Risk: memory counters in worker. Use Redis or bounded in-memory with expiry per process; acceptable for now if single worker.

Out of Scope
- Observer ingestion job; UI.
