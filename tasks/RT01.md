Goal
- Ensure all realtime consumers recover missed events when mounting offline or after connection loss.

Scope
- Frontend fallback logic; backend already provides history endpoint (B11).

Requirements
- On component mount: attempt realtime channel subscription.
- If subscription fails or no events received within 2s: call `GET /api/recent/:cluster_id` with `since=timestamp`.
- Merge pulled events into local state without duplicate rendering.
- Timestamp sourced from last known event timestamp in sessionStorage (or 5m ago if none).
- Applies to: presence list, typing indicator, arrival pill, activity feed.

Dependencies
- Realtime backend channels (B11) with history endpoint.
- FE08 (Realtime UX components) for component boundaries.

Plan
- Add `useRealtimeWithFallback` hook wrapping subscription + initial pull.
- Implement merge strategy: dedupe by event_id; preserve order by server_timestamp.
- Add timeout guard (2s) before triggering fallback.
- Add tests: offline mount → online → events appear without flicker.

Files to Touch
- `apps/web/src/hooks/useRealtimeWithFallback.ts`
- `apps/web/src/hooks/useRealtimeWithFallback.test.ts`

Validation
- Disconnect WebSocket → reconnect → missed events appear via pull.
- Fresh mount with no sessionStorage → pull last 5m; no duplicates on subsequent realtime events.

Risks & Mitigations
- Risk: Race between pull response and new realtime event. Mitigate with idempotent merge.
- Risk: Large history payload. Mitigate with 5m window and pagination.

Out of Scope
- Backend history endpoint implementation (covered by B11); offline caching beyond sessionStorage.
