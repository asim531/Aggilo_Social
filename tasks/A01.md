Goal
- Wire Clio prompt assembly to include observer Layer 4 signals with veto-window handling, **plus per-recipient soul manifestation profile and active persona override in Layer 3**.

Scope
- Clio prompt builder and loader; no UI.
- **Expanded:** L3 inputs now include **per-recipient** `soul_manifestation_profile[recipient_type]`, `active_persona_override`, and `agent_maturity`.

Requirements
- Read `observer_prompt_updates` and `clio_observer_signals` with TTL; only include non-expired updates.
- Apply veto window: if update is within veto period and veto flag set, skip injection.
- Preserve Layer order: L1 Soul, L2 Platform Rules + Clio character, L3 cluster identity (per-recipient), L4 per-call signals (incl. observer signals and history).
- **L3 cluster identity expansion (per-recipient):**
  1. Read `recipient_type` from auth context (e.g., `parent_as_facilitator`, `child_as_learner`)
  2. After `purpose, tags, arc_phase, member_count`, inject `soul_manifestation_profile[recipient_type]` block (≤120 tokens)
  3. If recipient-specific profile absent, fall back to `soul_manifestation_profile.default`
  4. Append any `special_directives` from the recipient's profile
  5. Note `active_persona_override` and `agent_maturity` (initial_confidence, expression_style)
- **Ecosystem context (NEW):** Inject `cluster_ecosystem_spec` summary into L3 (≤200 tokens):
  - `ecosystem_phase` (Seed/Sprout/Canopy) — Clio adjusts explanation depth accordingly
  - `success_model` top 2 dimensions by weight — Clio frames conversations around these priorities
  - `progression_model` current stage (if applicable) — Clio knows where the member is in their journey
  - `tool_requirements` active tools — Clio can reference them naturally
  - **Example:** If `conceptual_understanding` is top dimension, Clio asks "Can you explain why?" not "What's the answer?"
- **Feature awareness:** If cluster has pre-spawned features, include `feature_spawn_candidates` (already spawned) in L3 context so Clio can reference them.
- **Audit:** `clio_conversations.manifestation_profile_snapshot` must be populated with the **full per-recipient map** on session creation.
- Log applied/ignored updates, `recipient_type`, and trim events for audit.

- **A08 (soul manifestation generation) for per-recipient profile availability.**
- **B08 (migration 023) for feature proposal and ecosystem tables.**
