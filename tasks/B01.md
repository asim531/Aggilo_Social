Goal
- Define database schema for DM system per Phase 1 spec (request/accept, cross-cluster merge, single thread per user-pair).

Scope
- Migrations and ERD updates only.

Requirements
- Tables:
  - dm_threads: id, user_a, user_b, origin_cluster_id, created_at, last_message_at, status.
  - dm_requests: id, thread_id, sender_id, recipient_id, intro_text, status (pending/accepted/declined/expired), expires_at.
  - dm_messages: id, thread_id, sender_id, body (text-only), created_at.
  - connections: id, user_a, user_b, created_at, origin_cluster_id.
- Constraints:
  - Single thread per user pair (unique on sorted user_a/user_b).
  - Request must be accepted before messages allowed (except initial request message if stored).
  - Expiry default 30 days; silent decline allowed.
- Indexes on thread_id, sender_id, created_at.
- RLS policies (if applicable) for participant-only access.

Dependencies
- None.

Plan
- Draft SQL migrations for four tables with constraints and indexes.
- Add unique constraint for user pair in dm_threads.
- Document ERD and notes on merge rule.

Files to Touch
- `supabase/migrations/*` (or project migration folder)
- `docs/erd.md` (if exists)

Validation
- Run migrations locally.
- Insert sample threads/messages to ensure unique constraint and RLS (if present) behave.

Risks & Mitigations
- Risk: RLS complexity. Start with owner-only access; refine in B02.
- Risk: nullable origin_cluster_id; ensure indexing and merge logic consider null.

Out of Scope
- API endpoints; UI; realtime subscriptions.
