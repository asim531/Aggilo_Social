Goal
- Implement Part 6 §36 validator → retry → degrade flow for all agent LLM operations.

Scope
- Agent LLM call wrapper and tests. No prompt changes.

Requirements
- Validator hook runs post-LLM response; on failure: retry twice with backoff (per spec) then degrade path.
- Degrade path returns safe minimal response or silent failure flag per operation key.
- Log each attempt with status to llm_response_logs including validator failure reason.
- Expose meltdown counter per op: 3 validator failures/hour triggers Observer Domain 5 event (record in logs or queue trigger stub).

Dependencies
- Prompt builder (F03) in place; op-key registry (F02).

Plan
- Identify shared LLM call utility; add validator + retry + degrade pipeline.
- Add configurable retry/backoff, degrade handler map by op key.
- Add logging for attempts and failure reasons; increment meltdown counter.
- Add unit tests covering pass, retry success, degrade invoked, meltdown threshold increment.

Files to Touch
- `apps/api/src/lib/llm-client.ts` (or equivalent)
- `apps/api/test/llm-client.test.ts`

Validation
- Run tests.
- Simulate validator failure → observe retries and degrade path logged.
- Simulate 3 failures within hour → meltdown counter increment recorded.

Risks & Mitigations
- Risk: silent swallow. Mitigate with structured logging and explicit degrade return shape.
- Risk: infinite retry. Mitigate with fixed attempts and circuit break on validator hard-fail.

Out of Scope
- Changing prompts; changing model routing.
