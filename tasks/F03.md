Goal
- Assemble prompts with 4-layer inheritance contract enforcing token ceilings and trim order, **including per-recipient soul manifestation profile injection and cluster persona override merging**.

Scope
- Prompt builder code and tests only.
- **Expanded:** L3 assembly queries `cluster_specs.spec.soul_manifestation_profile[recipient_type]` (per-recipient map); L2 assembly checks `cluster_persona_overrides`; L3 includes `recipient_type` from auth context.

Requirements
- Layer order: 1) Soul, 2) Platform Rules + agent character, 3) Cluster identity (per-recipient), 4) Per-call signals/history.
- Token ceilings: L1 ≤600, L2 ≤800, L3 ≤400, L4 trims oldest history first.
- Overflow strategy: trim L4 oldest→newest until under limit; then compress L3 to key fields; **then compress per-recipient soul_manifestation_profile block to single-line summary**; if still over, throw structured error (no silent drop).
- **L2 persona resolution:** Load global persona → check `cluster_persona_overrides` → if active, merge `recurring_phrases`, `words_never_used`, `emoji_rules`, `humour_style`, `greeting_template` → preserve structural fields (register, formality, interjection_frequency).
- **L3 cluster context (per-recipient):**
  1. Read `recipient_type` from auth context (e.g., `parent_as_facilitator`, `child_as_learner`). Inferred by system, not self-declared.
  2. After `purpose, tags, arc_phase, member_count`, inject `soul_manifestation_profile[recipient_type]` block (≤120 tokens).
  3. If recipient-specific profile absent, fall back to `soul_manifestation_profile.default`.
  4. If no profile at all, infer from `vibe_characterization` + `inferred_composition`.
  5. Append any `special_directives` from the recipient's profile to Layer 3.
- Logging: record tokens used, trim events, and `recipient_type` to llm_response_logs for audit.

Dependencies

- **B08 (schema); B13 (migration 022) for per-recipient soul_manifestation_profile availability.**
