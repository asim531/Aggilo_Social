Goal
- Build notification service for FCM token handling and per-cluster/user preferences including quiet hours.

Scope
- Backend service + APIs + schema migrations.

Requirements
- Schema: notification_tokens (id, user_id, token, platform, last_seen, active), notification_prefs (user_id, cluster_id nullable, mute_all, mute_cluster, quiet_hours_start/end, updated_at).
- Endpoints: register token, delete token, update prefs (global + per-cluster), list prefs.
- Quiet hours respected in later push integration (store now).
- Basic validation: token length, platform enum.

Dependencies
- Auth middleware; FCM client later for push.

Plan
- Add migrations for tokens and prefs tables with indexes.
- Implement Fastify routes for register/delete/update/list.
- Add service to upsert tokens and prefs.
- Tests for register/update flows and validation.

Files to Touch
- `supabase/migrations/*`
- `apps/api/src/routes/notifications/*.ts`
- `apps/api/src/services/notifications.ts`
- Tests under `apps/api/test/notifications.test.ts`

Validation
- Register token → stored; update prefs → persisted; list shows cluster/global prefs.

Risks & Mitigations
- Risk: token churn. Update last_seen on register; dedupe by token.
- Risk: platform enum drift. Keep enum small (ios/android/web).

Out of Scope
- Actual push send (handled with B12 integration).
