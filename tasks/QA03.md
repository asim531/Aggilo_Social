Goal
- Validate end-to-end flows for generic and premium cluster creation, from user intent capture through Genesis, Ecosystem defaults, and initial agent behaviour (Clio + Sage).

Scope
- Manual and scripted tests only (no new product features).

Requirements
- Generic cluster flow:
  - Scenario: member asks Clio for a new room (no existing crowd).
  - Verify:
    - Clio asks for one **concrete recent situation** and **size/frequency** as per `CLIO_SYSTEM_PROMPT`.
    - Clio shows similar clusters before creating a new one.
    - Backend receives a `ClusterRequirement` with correct `who`, `size_hint`, `frequency_hint`, `pain_points`, `desired_outcome_type`.
    - Genesis produces a `cluster_genesis_spec` with sensible `ecosystem_type`, `social_layer_default`, and `progression_model`.
    - Ecosystem config spawns the right default tools for that spec.
    - Sage’s first posts reflect the `ecosystem_type` + `social_layer_default` (tone, cadence) and only mention active tools.

- Premium cluster flow (Make Your Crowd):
  - Scenario: guardian describes an existing crowd (10–500 regulars) and pain with current tools.
  - Verify:
    - Clio routes to Premium application path instead of generic creation when crowd is detected.
    - Premium form captures credibility and pain per PRD 12.
    - Intake pipeline (Pattern 7) generates v1 + adversarial critique + v2 and surfaces them in admin UI.
    - Backend normalises the application into a `ClusterRequirement` with `source = 'premium_application'`.
    - Genesis produces a spec with hard location/language gates and guardian-admin role.
    - Ecosystem config yields correct default surfaces (guardian dashboard, learner surface, social overlay default) for that archetype.
    - First-run Sage posts and Clio onboarding reflect this spec.

Validation
- Document test cases and their expected results.
- Provide screenshots or logs for at least one generic and one premium cluster going from intent → Genesis → live cluster.
- Raise follow-up bugs/tasks for any misalignments between architecture, prompts, and runtime behaviour.
