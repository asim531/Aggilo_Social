Goal
- Build Sage context assembler ensuring cluster-scoped data only; prepares arc phase state for anchor behaviors, **including per-recipient soul manifestation profile and composition-aware context**.

Scope
- Assembler code and tests; no UI changes.
- **Expanded:** L3 inputs include **per-recipient** `soul_manifestation_profile[recipient_type]`, `inferred_composition`, `feature_spawn_candidates` (spawned), and `agent_maturity`.

Requirements
- Inputs: cluster_id → fetch cluster purpose, tags, arc_phase, arc_phase_since, member_count, recent posts (cluster-only), Atlas refinement history (cluster-only), poll results, active cluster tools, **per-recipient `soul_manifestation_profile`**, **inferred_composition**, **spawned features**, **agent_maturity**, **cluster_ecosystem_spec**.
- Exclude any data from other clusters even if same user is member (hard constraint).
- Outputs structured context object for Sage LLM calls; includes arc_phase and last change, sage_last_posted_at, reengagement_sent_at, **per-recipient soul_manifestation_profile block**.
- **Per-recipient register alignment:**
  - Read `recipient_type` from auth context. Inject `soul_manifestation_profile[recipient_type]` into L3.
  - If `parent_as_facilitator`: `primary_register: "inquiry"` → Sage uses questioning tone, offers practical next steps.
  - If `child_as_learner`: `primary_register: "playfulness"` → Sage uses playful patience, visual language.
  - If recipient ambiguous, fall back to `soul_manifestation_profile.default`.
- **Ecosystem-aware behavior (NEW):**
  - Load `cluster_ecosystem_spec` into L3 context (≤200 tokens)
  - Pass `success_model` top dimensions — Sage frames posts around these priorities
  - Pass `progression_model` current stage — Sage teaches toward stage mastery criteria
  - Pass `tool_requirements` active tools — Sage references them as scaffolding
  - **Example:** If `conceptual_understanding` is top dimension, Sage posts: "I wonder why 1/2 and 2/4 are the same?" not "The answer is 2/4."
  - **Example:** If `joy_of_mathematics` is active, Sage celebrates curiosity and effort, not just correctness
  - If ecosystem_phase is `seed`, Sage expresses more calibrated uncertainty: "I'm still learning what works here."
  - If ecosystem_phase is `canopy`, Sage can ask members for input: "What would help you most right now?"
- **Composition-aware curation:** When curating Atlas content, weight toward highest-weight tags in `inferred_composition`. Pass `inferred_composition` to Atlas brief.
- **Feature awareness:** Include spawned features in L3 so Sage can reference them naturally (e.g., "Try the adaptive quiz").
- **Calibrated uncertainty:** Pass `agent_maturity` to L3. When `initial_confidence: "learning"`, Sage expresses honest uncertainty in posts.
- Unit tests to assert no cross-cluster bleed (simulate user in multiple clusters).
- **Unit tests for per-recipient alignment: inquiry → no lecture; playfulness → visual language.**

Dependencies
- DM/cluster schemas (B01), cluster creation constraints (B10) for arc init fields.
- **A08 (soul manifestation generation) for per-recipient profile availability.**
- **B08 (migration 023) for composition/feature and ecosystem tables.**
- **B09 (Observer stewardship) for ecosystem health snapshots.**

Plan
- Implement assembler module that takes cluster_id and pulls scoped data.
- **Inject per-recipient `soul_manifestation_profile` via `loadSoulManifestationProfile(clusterId, recipientType)` into L3 context.**
- **Pass `inferred_composition` to Atlas brief for composition-aware curation.**
- **Pass spawned `feature_spawn_candidates` into L3 for feature awareness.**
- **Pass `agent_maturity` into L3 for calibrated uncertainty.**
- **Load `cluster_ecosystem_spec` and inject success model + progression model + tool requirements into L3 context.**
- Add register alignment check per recipient: warn if Sage configuration contradicts `primary_register`.
- Add guard to reject if cluster_id missing or user not member (where applicable).
- Write tests with fixtures: user in two clusters, ensure data is only for requested cluster; per-recipient tone varies.
- **Add tests for ecosystem-aware behavior: conceptual_understanding top dimension → understanding-focused posts; joy_of_mathematics active → effort celebration.**
