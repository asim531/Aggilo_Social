Goal
- Implement moderation pipeline with AI pre-screening, severity tiers, and admin handling.

Scope
- Backend moderation service, schemas, endpoints; no UI.

Requirements
- Schemas:
  - moderation_flags: id, source (post/comment/dm), source_id, user_id, reason_ai, severity (critical/high/medium/low), status (open/reviewed/actioned), created_at.
  - reports: id, source_type, source_id, reporter_id, reason_text, status, created_at.
- AI pre-screen hook on post/comment creation: assign severity, insert moderation_flags.
- Endpoints: list flags (admin), update status/action, submit report (user).
- Severity rules align with Observer Domain 8 (critical → immediate admin attention).

Dependencies
- Auth (admin vs user), content tables (posts/comments/dm_messages), AI classifier stub/service.

Plan
- Add migrations for moderation_flags and reports.
- Implement AI pre-screen stub (pluggable) invoked in post/comment create path.
- Add routes for user report submission and admin review/update.
- Tests for flag creation, report submission, status transitions.

Files to Touch
- `supabase/migrations/*`
- `apps/api/src/services/moderation.ts`
- `apps/api/src/routes/moderation/*.ts`
- Hook in post/comment creation handlers
- Tests under `apps/api/test/moderation.test.ts`

Validation
- Create post → AI stub inserts flag with severity; report endpoint creates report; admin list shows items; status update works.

Risks & Mitigations
- Risk: over-flagging with stub. Keep stub configurable; allow bypass in dev.
- Risk: performance impact. Run AI call async if needed; initial stub sync minimal.

Out of Scope
- UI; human moderation workflows; DM content rendering (just IDs).
