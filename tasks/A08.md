Goal
- Genesis Engine deeply infers cluster composition from founder's free-text description and generates a full spec including per-recipient `soul_manifestation_profile`, feature spawn candidates, and vibe characterization.

Scope
- Genesis Engine spec generation (Cycle A Step 1–2) and introspection logic (Step 3).

Requirements
- **Free-text intake:** Founder provides single `description` text (no questionnaire). Stored in `cluster_intent_responses`.
- **Deep LLM inference (Cycle A Step 1):** Send `description` + founder AGGIL profile to LLM. Infer:
  - `inferred_composition`: weighted tag map (0.0–1.0) with confidence and rationale
  - `stakeholders`: roles with needs, pain points, communication style
  - `feature_spawn_candidates`: tools/features with probability, confidence, trigger, ui_placement, auto_spawn flag
  - `vibe_characterization`: primary_mood, energy_level, formality, humour, urgency, growth_mindset, community_temperature, rationale
  - `cluster_spawn_risk`: probability_of_spawn, potential_sub_clusters
  - `agent_maturity`: initial_confidence, expression_style
  - **`cluster_ecosystem_spec` (co-generated):** ecosystem_type, success_model, progression_model, tool_requirements, introspection_targets (see `architecture/CLUSTER_ECOSYSTEM.md` §9 Schema)
  - **`purpose_type` inference:** `impartial_service` | `social_learning` | `peer_support` | `expert_guided`
  - **`domain_profile` inference (clusters with ordered progression):** beneficiary demographics, geography, scope/context, full progression stages with prerequisites, common misconceptions, transfer_domains
- **Adaptive Probing (NEW, premium clusters only):**
  - After Pass 1, check confidence scores against thresholds (see `CLUSTER_GENESIS_ENGINE.md` §2.3)
  - For dimensions below threshold, generate 1-3 targeted follow-up questions
  - Founder answers (can be over multiple messages, can skip)
  - Re-infer with accumulated answers; update confidence scores
  - Repeat until all dimensions ≥ threshold OR max 5 probe rounds reached
  - Store probe Q&A in `genesis_probe_responses` table
- **Per-recipient soul_manifestation_profile (Cycle A Step 2):**
  - Generate per-recipient map keyed by stakeholder type
  - Each recipient profile includes: primary_register, scripture_usage, silence_expectation, vulnerability_surface, conflict_mode, celebration_mode, special_directives
  - Include `default` profile for recipients without specific mapping
  - Validation: each recipient profile passes enum checks
- **Feature pre-spawn:** After spec generation, evaluate `feature_spawn_candidates`. Auto-spawn if `probability >= 0.70` AND `auto_spawn: true`. Queue others as `cluster_feature_proposals`.
- **Stakeholder relationship dynamics (NEW):**
  - Infer `intended_goals`, `relationship_dynamic`, `transition_expectations`, `interaction_patterns` per stakeholder
  - Store in `cluster_genesis_spec.stakeholders` JSONB
  - Used by Sage for calibrated responses; used by Observer for relationship drift detection
- **Vault alignment check (NEW):**
  - Stage 1: Rule-based screening (curriculum level, stakeholder, subject, purpose, ecosystem fit)
  - Stage 2: LLM edge-case evaluation (alignment_score 0.0–1.0; questions if 0.50–0.80; auto-approve if ≥ 0.80)
  - Founder answers alignment questions → LLM re-evaluates → approved or rejected
  - Store results in `cluster_vault_items` (alignment_check_status, alignment_score, alignment_questions, alignment_reason)
- **Cluster fit assessment (NEW):**
  - Search existing clusters by purpose_type, domain_profile, beneficiary, service_mode, geography, language, activity level
  - Present 0-3 matches to founder with match score, pros, cons
  - Log decision in `genesis_probe_responses` and `cluster_fit_decision` table
- **Introspection validation (Step 3):** Validate against platform rules. Flag low-confidence inferences (`confidence < 0.60`) for admin review.
- Write `soul_manifestation_audit` row on creation.

Plan
1. Implement `deepInferClusterSpec(founderDescription, founderProfile, platformContext)` — single LLM call returning full inferred spec with confidence scores per dimension
2. **Implement `generateProbeQuestions(spec, thresholds)` (NEW):** Identifies dimensions below threshold, generates 1-3 targeted questions per round
3. **Implement `reInferWithProbes(spec, probeResponses)` (NEW):** Re-runs inference with accumulated founder answers, returns updated confidence scores
4. **Implement `runAdaptiveProbeLoop(founderDescription, founderProfile, platformContext)` (NEW):** Orchestrates Pass 1 → probe generation → founder answers → Pass N loop until thresholds met or max rounds reached
5. Implement `generatePerRecipientManifestationProfile(inferredComposition, stakeholders, vibe)` — generates map with `default` + stakeholder keys
6. Implement `validatePerRecipientProfile(profileMap)` — iterates all keys, validates enums
7. Implement `spawnHighProbabilityFeatures(featureCandidates)` — auto-spawn >= 0.70 prob, queue rest
8. **Implement `runVaultAlignmentCheck(vaultItem, clusterGenesisSpec)` (NEW):** Two-stage check

   - Store results in cluster_vault_items table
