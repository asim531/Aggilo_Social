Goal
- Implement Scout's directed data-acquisition job queue and persist result reports with confidence scores.

Scope
- Backend job submission, execution, and persistence only; no frontend.

Requirements
- Scout accepts directed job requests (source target, query parameters, cluster context).
- Jobs are enqueued via BullMQ with idempotency key (source + query hash).
- On completion: persist report row with confidence (0.0–1.0), source URL/title snippet, and cluster_id.
- Failed jobs retry twice, then degrade to manual-review queue (Observer Domain 5).
- Report rows are cluster-scoped; no cross-cluster bleed.

Dependencies
- Observer stewardship tables (B09) for manual-review queue.
- BullMQ idempotency (F05) for deduplication.
- Data Acquisition pipeline (external — Scout agent runtime).

Plan
- Add `scout_jobs` and `scout_reports` tables (migrations).
- Implement job submitter with idempotency key and BullMQ enqueue.
- Implement result handler that writes report rows on job success.
- Add retry logic (2 attempts) and degrade path to Observer on exhaustion.
- Add unit tests for enqueue, dedup, success, failure, degrade.

Files to Touch
- `apps/api/src/services/scout-jobs.ts`
- `apps/api/src/services/scout-reports.ts`
- `apps/api/test/scout-jobs.test.ts`

Validation
- Submit same job twice → second rejected with idempotency collision.
- Successful job → report row exists with confidence and cluster_id.
- 3 failures → Observer Domain 5 record created; no infinite retry.

Risks & Mitigations
- Risk: Data Acquisition pipeline latency. Mitigate with timeout and degrade.
- Risk: Confidence score calibration. Mitigate with manual audit sample.

Out of Scope
- Scout agent model/training; UI for viewing reports; auto-ingestion into Atlas.
