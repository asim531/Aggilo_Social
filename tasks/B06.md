Goal
- Create schema and endpoints to store organic feature signals from Clio conversations.

Scope
- DB migrations + capture/list API; no Observer job (see A07).

Requirements
- Table feature_signals: id, feature_hash, scope (cluster|cross), cluster_id nullable, status (captured|observer_reviewed), frequency_count, first_seen, last_seen, sample_quote (no PII), observer_reviewed_at/by.
- Hash dedup: normalized/stemmed text; increment frequency_count on match.
- API: POST /api/feature-signals (internal/Clio) to capture; GET /api/feature-signals/aggregated (admin) returns aggregated counts (no user_id ever).
- RLS/admin gating as appropriate.

Dependencies
- Auth (internal/admin scopes); Clio pipeline will call.

Plan
- Add migration for feature_signals with indexes on feature_hash, status.
- Implement capture endpoint with validation (unsolicited only flag TBD via caller).
- Implement aggregated list endpoint for admin.
- Tests for dedup, create, list.

Files to Touch
- `supabase/migrations/*`
- `apps/api/src/routes/feature-signals/*.ts`
- `apps/api/src/services/feature-signals.ts`
- Tests under `apps/api/test/feature-signals.test.ts`

Validation
- Duplicate capture increments frequency_count; list shows aggregated counts; no PII stored.

Risks & Mitigations
- Risk: PII leak. Do not store user_id or raw message; only sample_quote scrubbed.

Out of Scope
