Goal
- Trigger push notifications when new activity rows are created, respecting preferences and quiet hours.

Scope
- Backend integration between activity service and notifications service; no frontend.

Requirements
- On insert into activity_events: check user prefs (mute_all, mute_cluster, quiet hours); if allowed, enqueue push send.
- Push payload minimal: title/body, deeplink to relevant screen (cluster/timeline/dm).
- Idempotent: avoid duplicate push for same activity id.

Dependencies
- Activity service (B03); notification prefs/tokens (B04); queue system.

Plan
- Add hook in activity service to call notification dispatcher.
- Implement dispatcher that filters by prefs and quiet hours; enqueues push job with idempotency key activity_id.
- Add tests for muted, quiet hours, and idempotency.

Files to Touch
- `apps/api/src/services/activity.ts`
- `apps/api/src/services/notifications-dispatch.ts`
- Tests under `apps/api/test/activity-notifications.test.ts`

Validation
- Creating activity with prefs ON sends one push; with mute or quiet hours, no push.
- Duplicate insert ignored via idempotency.

Risks & Mitigations
- Risk: time zone for quiet hours. Store in user local tz or UTC with offset; document choice.

Out of Scope
- Frontend handling of push; FCM client.
