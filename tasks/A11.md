Goal
- Implement the **ecosystem intake lens** as a first-class, cluster-agnostic normalisation step in the Intake Interpreter and Genesis Engine prompts/runtimes, without introducing rigidity.

Scope
- Prompt + runtime wiring only; no new tables (reuse `cluster_intake_drafts`, `cluster_specs`, `cluster_ecosystem_specs`).
- Intake Interpreter + Genesis jobs; no UI changes.

Requirements
- Intake Interpreter (Pattern 7):
  - Update the Intake Interpreter LLM prompt so that every Draft v1 explicitly infers an **ecosystem intake lens** from the raw signal, matching `CLUSTER_ECOSYSTEM.md` §1.7.
  - Lens dimensions to infer (using founder language, not taxonomy labels):
    - `failure_gaps`
    - `primary_outcomes`
    - `primary_stakeholders`
    - `interaction_mode`
    - `temporal_shape`
    - `social_layer_shape`
    - `tool_capability_needs`
    - `risk_profile`
    - `cadence_arc_hints`
    - `non_negotiables`
  - Represent the lens inside `cluster_intake_drafts.payload` as a JSON object (no new top-level table): `{ ecosystem_intake_lens: { ... } }`.
  - Ensure the lens is **descriptive, not prescriptive**:
    - No hard-coded archetype enums in this block.
    - Values are short natural-language summaries or light-typed fields (string/enum + free-text rationale).
  - Update the Adversarial Reviewer prompt to **challenge the lens** where it sees overreach or unjustified assumptions (e.g., inferring privacy requirements not supported by the signal).

- Genesis Engine (Pattern 8 / CLUSTER_GENESIS_ENGINE):
  - Update Cycle A prompts to **consume** `ecosystem_intake_lens` from Draft v2 when generating `cluster_genesis_spec` and `cluster_ecosystem_spec`.
  - Ensure that `cluster_ecosystem_spec` fields (`success_model`, `progression_model`, `tool_requirements`, `introspection_targets`) clearly reflect the intake lens dimensions.
  - Preserve **non-rigidity**:
    - Genesis can propose internal archetype mixes, but must not overwrite or narrow the lens; archetypes are advisory overlays.
    - Specs must allow future evolution via Observer/Evolution Governor without schema changes.
  - Add explicit tests/fixtures for:
    - A Long-Conversation-like request (depth conversation, no DMs/photos) → lens correctly encodes failure/gaps and non-negotiables without forcing “intimacy” as a type.
    - A Sisters-in-Dua-like request → lens shows faith_peer_support shape with privacy and non-negotiables.
    - A Research-Circle-like request → lens shows persistence, topic+documents interaction, and findability without enforcing the existing RC archetype.

Plan
- Update Intake Interpreter prompt templates to add the `ecosystem_intake_lens` block in Draft v1 payload.
- Update Adversarial Reviewer prompt to critique the lens fields alongside AGGIL/name/purpose.
- Wire Genesis Engine Cycle A prompt to read `ecosystem_intake_lens` and co-generate `cluster_genesis_spec` + `cluster_ecosystem_spec` accordingly.
- Add unit tests (or harness cases) around the three representative intents (LC, Sisters, RC) to ensure:
  - Lens is populated.
  - Specs mirror the lens.
  - No rigid archetype enforcement.

Files to Touch
- `apps/api/src/services/intake/intake-interpreter.ts` (or equivalent)
- `apps/api/src/services/intake/adversarial-reviewer.ts` (or equivalent)
- `apps/api/src/services/genesis/engine.ts`
- Corresponding tests under `apps/api/test/*`

Validation
- All new/updated tests pass.
- For three sample intents (LC/Sisters/RC-like), `cluster_intake_drafts.payload.ecosystem_intake_lens` and the resulting `cluster_specs.spec` + `cluster_ecosystem_specs.ecosystem_spec` stay aligned and do not collapse into a single rigid archetype.

Risks & Mitigations
- Risk: prompt bloat. Keep lens summaries concise (1–2 sentences per dimension); enforce token ceilings from F03.
- Risk: hidden rigidity (archetypes leaking into prompts). Keep archetype reasoning internal to Genesis and never surface archetype names in the lens block.
- Risk: misuse of lens as gate. Document in code comments and prompts that the lens is descriptive and must not be used to deny creation when the signal is valid.
