Goal
- Implement the full Clio-driven cluster creation overlay flow: unmet need, similar clusters, disambiguation, 3 questions, confirmation with constraints, success modal.

Scope
- Frontend UI/flows; backend calls mocked or wired when available.

Requirements
- States:
  - 5.1 Initiation: user message + Clio typing/searching; FAB overlay at bottom-right; background Explore live.
  - 5.2 Similar clusters: up to 3 compact cards with Join buttons; “These don’t fit” link.
  - 5.3 Disambiguation: targeted question + user reply; create/return buttons; honest mode if covered.
  - 5.4 Questions: sequential Q1–Q3 (one line desc, locality, age range); no progress bar; natural chat pacing.
  - 5.5 Confirmation: brief card with tags/who/age/location/purpose; gender lock pill; age slider snap-back to founder year; adjust/change buttons.
  - 5.6 Success: modal card “It is live.”, Clio 80px, CTA “Take me there”.
- Constraints UI: founder gender pre-selected + lock icon; age slider includes founder birth year (snap-back + tooltip on violation).
- Animations: shimmer/typing indicators, card fade/slide consistent with spec.
- Uses FE01 FAB component for panel shell.

Dependencies
- FE01 dual-tab FAB (panel shell); backend endpoints (B10) if available, else stub.

Plan
- Create overlay component with state machine across screens 5.1–5.6.
- Implement similar-cluster list component and stub API adapter.
- Implement confirmation card with locked gender pill and age slider snap-back.
- Implement success modal overlay.
- Add UI tests for flow transitions and constraint behaviors.

Files to Touch
- `src/components/ClioCreationPanel.tsx` (new)
- `src/components/ClioCreationCard.tsx` (new)
- `src/hooks/useClioCreationFlow.ts` (state machine)
- Tests under `src/components/__tests__/ClioCreationPanel.test.tsx`

Validation
- Walk through flow with stub data: unmet need → similar clusters → disambiguation → Qs → confirmation → success.
- Attempt to remove founder gender or exclude founder birth year → UI snap-back + tooltip.

Risks & Mitigations
- Risk: interaction with real backend later. Abstract API adapter to swap stub for real.
- Risk: animation perf. Keep animations minimal (200ms) per spec.

Out of Scope
